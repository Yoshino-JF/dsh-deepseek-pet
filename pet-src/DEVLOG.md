## 0. 一句话

一只悬浮在 Windows 11 桌面上的**蓝鲸女仆桌宠**，实时显示 DeepSeek 开放平台账户余额；
由 DSH 插件用凭据库里的 Key 查余额，再通过本机回环接口喂给它。

## 2. 架构与数据流

```
DSH 宿主插件 (@local/dsh-pet)                  桌宠进程 (DeepSeekPet.exe)
 ├ ctx.credentials.resolve(DEEPSEEK_API_KEY)   │  WPF 分层窗口：透明/置顶/不进任务栏
 ├ GET api.deepseek.com/user/balance           │  每 5 秒来取一次状态
 ├ 缓存 60s（先回缓存、后台补数据）             │  ← HTTP 127.0.0.1:47831/state?pid=<桌宠pid>
 ├ node:http 只监听 127.0.0.1                   │  失败 → 读 last-state.json，徽章转灰显「离线」
 └ spawn(detached) / command:quit ─────────────▶  pid 上报 = 插件判断桌宠是否活着
```

**安全边界**：API Key 只在宿主进程与凭据库里，桌宠进程从不接触密钥，只收余额数字与留言。

## 3. 关键实现

1. **透明置顶窗**：`WindowStyle=None` + `AllowsTransparency=true` + `Topmost` + `ShowInTaskbar=false` + `ShowActivated=false`（点它不抢焦点）。
   分层窗口里 alpha=0 的像素天然鼠标穿透，所以空白区域不会挡桌面。
   DPI 用 `app.manifest` 声明 system-aware；本机 125% 缩放下坐标按 DIP 计算。
2. **布局**：三行 Grid＝气泡（固定 88px 占位，避免说话时立绘跳动）/ 立绘 / 余额徽章，另叠一层不接收鼠标的 Canvas 放气泡粒子。
3. **素材管线**（`pet-tools key`）：四角采样背景色 → 颜色距离线性映射成 alpha → 按 alpha 反解去背景溢色 → 只保留最大连通块（顺手丢掉飘散的气泡装饰）→ 裁边 → `scale` 到 720px。
4. **动画**：双层 `Image` 交叉淡入换表情（320ms）；`TransformGroup(Scale/Rotate/Translate)` 驱动呼吸与摇摆；眨眼＝240ms 关键帧盖一层 `blink.png`；粒子＝定时生成 `Ellipse` + 位移/透明度动画。
5. **数据链路**：`/state` 永远先回缓存（桌宠不等网络），后台按 60s TTL 补一次；失败时桌宠侧回退读 `%APPDATA%\deepseek-pet\last-state.json` 并标记离线。
6. **进程生命周期**：插件用 `detached + stdio:'ignore'` 拉起桌宠，**DSH 重启不影响它**；桌宠单实例互斥；宿主启动 3 秒后自动叫起；桌宠每次取状态带自己的 pid，插件据此判断存活，对非自启实例用 `command:'quit'` 软退出。
7. **交互与持久化**：拖动移动、单击蹦跳+台词、双击开心、滚轮缩放、右键菜单（刷新/表情/动画/大小/复位/置顶/关于/退出）、托盘图标；位置与缩放写回 `%APPDATA%\deepseek-pet\config.json`。

### 表情状态机（v0.0.1）

| 形态 | 触发条件 |
|---|---|
| 普通 idle | 默认；余额正常且 6 分钟内有互动 |
| 眨眼 blink | 每 2.6–6.2 秒随机一次，叠在任意表情上 240ms；开心后 1.2–1.8 秒内不眨 |
| 开心 happy | 单击/双击；或余额上升（充值到账 ≥ ¥0.01） |
| 担心 worry | 余额 < `lowBalance`（默认 ¥10）或账户不可用 |
| 困倦 sleepy | 6 分钟无任何互动（悬停/点击/拖动都算互动） |
| 手动强制 | 右键菜单「表情」，写入 `moodOverride` |

另有 3 种非表情小动作：呼吸+摇摆、海底气泡粒子、点击蹦跳（都可在右键菜单关掉）。

## 5. 已知限制

- **同包替换插件代码需要重启 DSH**（上游语义：`install_bundle` 返回 `restart-required`），光重装不会加载新 JS 世代。
- DSH 未运行时桌宠仍在桌面，但余额是灰显的缓存值（这是刻意的，避免桌宠跟着 DSH 一起消失）。
- 只有 5 张静态立绘 + 程序化动画，没有逐帧动画 / Live2D。
- 空转内存约 138 MB、每 5 秒一次 HTTP 轮询；无操作时也不会降频。
- 无鼠标穿透模式、不记忆多显示器、无开机自启、无逐会话状态联动。
- **核对窗口/截图必须先让进程 DPI-aware**：本机 2560×1440 @125%，unaware 进程只能截到左上角 2048×1152（开发期在这上面栽过一次）。

## 6. Roadmap（优化方向）

> 估时按"我 + 你验收"的节奏给：S ≤ 半天，M ≈ 1 天，L ≥ 2 天。

### R1 · 余额消耗显示（你提的）— P0 / S
- **目标**：不只显示"还剩多少"，还显示"上次/今天消耗了多少"，且**不要高频刷新**。
- **做法**：插件在每次刷新时比较 `total` 与上次快照，只在下降时记录 `spend = { last, at, today }`（跨零点滚动），随 `/state` 下发；桌宠徽章加第二行 `上次 -¥0.42`，余额下降时弹一句气泡 + 短暂"肉疼"表情。同时把 `refreshSeconds` 默认从 60 提到 **300**（余额本来变化就慢），只在你主动问或充值/明显消耗时立即刷。
- **更准的口径（推荐）**：真正的花销在 DSH 会话日志的 token 用量里（按 provider/model 单价算），可以额外提供"本次会话已消耗 ¥x.xx"——比余额差更精确，也不必频繁请求接口。
- **验收**：连续两轮对话后桌宠显示 `上次 -¥0.25 / 今日 -¥1.37`，且与 token 用量报告对得上。

### R2 · 桌前场景 + 游戏屏动画（你提的，v0.0.2 旗舰项）— P1 / L（拆 3 步）
- **定位**：这条是跟"可爱路线"桌宠的分水岭 —— 别人的桌宠是**挂件**，我们的是**会自己玩的小室友**：屏幕上真的在跑游戏，动作有前因后果，还会被苦力怕炸。**不接受"贴个图标"的偷懒做法**。
- **场景与图层**（窗口放大到约 480×360 DIP，四层）：
  1. `desk_base`：桌子 + 显示器（屏幕区域留空）+ 椅子 + 坐姿立绘（待机 / 睡觉 / 玩游戏，交叉淡入）
  2. **屏幕图层**（显示器矩形内，独立渲染）：运行时切换"游戏屏"
  3. 前景道具层：水杯、键盘、手柄、零食（可被拖动/投喂的交互对象）
  4. 气泡与粒子层（沿用现有）
- **四种"游戏屏"脚本**（点显示器＝切下一款；每款 10–20 分钟随机轮换）：

  | 屏 | 画面 | 动画脚本 |
  |---|---|---|
  | **Minecraft（默认）** | **不放图标，直接放第一人称游戏画面**（纯代码画的像素画，零美术资源） | ① 右手斧子挥砍（3 帧）→ ② 树干裂纹、方块碎裂飞散 → ③ 原木计数 `+1` 飘字 → ④ 约 8% 概率插播：苦力怕嘶嘶逼近 → 白闪 → **You Died** 红屏 → ⑤ 2 秒后 respawn 回到 ① |
  | 柚子社 | 官方 logo 的**简笔画版** | Galgame 式：立绘剪影 + 对话框**逐字打字机**，偶尔弹出选择支 |
  | Steam | 库页面简笔画 | 下载进度条缓慢爬升 + "正在更新…"，成就横幅滑入 |
  | Xbox | 主页 / 成就简笔画 | 绿色成就横幅弹出（"已解锁：今天也没摸鱼"）+ 手柄轻微震动抖动 |

- **小动作池**（避免重复感：权重 + 冷却 + 互斥）：
  `伸懒腰 / 喝水 / 转笔 / 看手机 / 敲键盘 / 挠头 / 趴桌睡(Zzz) / 玩游戏 / 被炸后懵住 3 秒`
  调度：动作播完再抽下一个（权重随机），同一动作 10 分钟内不重复；**外部事件可插队**（余额下降、充值到账、DSH 开始干活/答完）。
- **状态机**：`desk_idle`（桌前待机）→ 6 分钟无互动 → `desk_doze`（趴睡 + Zzz）→ 随机 2–5 分钟 → `desk_game`；
  任何互动（点击 / 拖动 / DSH 干活）打断回 `desk_idle`；"被炸懵"是 3 秒可打断插播。
- **素材清单**：`assets/desk/base_{idle,sleep,game}.png`（720×540 透明 PNG）、`assets/desk/props/*.png`（水杯/手柄/零食 128px）；
  **屏幕内容全部代码绘制**（MC 第一人称、Steam 进度条、Xbox 横幅、柚子社对话框），第三方 logo 才走小图 → 见第 11 节 IP 策略。
- **拆分与估时**：R2a 场景窗口 + 3 张坐姿立绘 + 点屏换游戏（1 天）→ R2b Minecraft 屏完整剧本（半天，纯代码）→ R2c 另三款屏 + 小动作池调度（1 天）。

### R2d · 「被叫去干活就炸」事件剧（你提的，R2 × R4 的招牌动作）— P0 / S
**这是本插件最有辨识度的一条：随机被炸只是装饰，"你叫它干活 → 它吓一跳 → 手忙脚乱 → 被炸"才是叙事。**

- **剧本**（一次 4–6 秒演完，全程由真实事件驱动）：

  | 时间 | 状态 | 演出 |
  |---|---|---|
  | 0.0s | `desk_game` | 正在砍树（R2b 循环） |
  | 收到事件 | `startled` 0.4s | 椅子后仰、眼睛瞪圆（复用 worry+blink 叠加）、手柄一抖、头上冒「！」 |
  | +0.4s | `scramble` 0.4s | 屏幕闪切成终端/代码行 —— 来不及了 |
  | +0.8s | `creeper` 0.8s | 嘶嘶声波纹 + 白闪 |
  | +1.6s | `you_died` 1.2s | 红屏 + "You Died" + 它自己僵在原地 |
  | +2.8s | `respawn` | 屏幕回到游戏 → 切走 |
  | +3.2s | `desk_work` | 坐正敲键盘，与 R4 的「写代码中」角标合流 |

- **触发判定（关键，别让自动任务吓它）**：`agent/inbox/inserted`（用户消息进入 inbox）之后 **10 秒内** `agent/status` 变为 `running`，才算"被用户叫去干活"；
  自动续跑（auto-continue）、子代理、定时任务**不触发**。两个事件名已用 `cordis_inspect_query` 核实存在，且是"监听"而非轮询 `agent/status`。
- **三条护栏（全部进 config，默认值偏保守）**：

  | 参数 | 默认 | 作用 |
  |---|---|---|
  | `interruptChance` | `0.6` | 被打断时"炸掉"的概率 —— 不是每次都炸，否则第 5 次就变复读 |
  | `interruptCooldownMin` | `10` | 两次"被炸"的最短间隔；冷却期内改成**叹气后乖乖切屏**（递进，不复读） |
  | `onlyUserInitiated` | `true` | 只对用户主动发起的回合反应 |
  | `animMaxShiftPx` | `12` | 惊吓位移上限 —— 表演要短促，别在用户眼皮底下乱跳 |

  演出期间窗口**不激活、不发声**，点一下立刻中断回到桌前待机。
- **性能前提**：必须把反应延迟压到 **< 100 ms**，否则喜剧节奏全毁（现在 5 秒轮询 = 最坏晚 5 秒才炸）。
  → 桌宠改**长轮询**：`GET /state?wait=25`，插件把请求挂起最多 25 秒、有事件立刻返回（`node:http` 约 20 行）。
  顺带让余额变化、`pet_control say` 的留言也变成即时推送，而不是等下一个轮询周期。
- **两个变体（让它更像活的）**：
  1. **玩上头**：超过 1 小时没被打断过，触发时"炸掉"的概率上调（它玩得更投入）。
  2. **记仇三分钟**：被炸后 3 分钟内台词变委屈、不主动开游戏；**充值到账立刻原谅你**（切开心 + 撒花）。

### R3 · 拖拽"拎起衣服"动画（你提的）— P0 / M
- **目标**：按住拖动时，鲸鱼娘被拎住衣领悬在空中，松手落地。
- **做法**：新增 `held.png`（被拎起、双腿离地微摆、衣褶下垂）＋ 可选 `drop.png`（落地压缩帧）。`MouseDown` 立刻切 `held`，把 `RenderTransformOrigin` 改到顶部 (0.5, 0.02)，拖动中做 ±6° 钟摆（带一点滞后感）；松手 → 200ms 落下 + `ScaleY` 压到 0.94 回弹 + 落地扬尘粒子 → 回 idle。
- **技术风险（要先验证）**：现在拖动用的是 `DragMove()`，它会**阻塞 UI 线程直到松手**——需要实测这期间动画是否还在走（WPF 渲染线程独立，通常仍在跑）；若被卡住，就改成手动拖动（`MouseMove` 里改 `Left/Top`）换取动画自由度。

### R4 · 跟随 DSH 干活状态（我补的，最推荐）— P0 / S
订阅宿主侧的回合事件（agent/turn 相关），把 `busy / label` 放进 `/state`：思考中… / 写代码中… / 答完啦。
桌宠显示小角标 + 敲键盘的轻微抖动，回合结束时蹦一下。**这一条最能让它像"DSH 的桌宠"而不是"一个显示余额的小挂件"**，而且几乎不需要新立绘。

### R5 · 鼠标穿透 + 抓手（我补的）— P1 / S
右键菜单开「锁定」：`WS_EX_TRANSPARENT` 让点击穿透，只留一个 20×20 的抓手区域；配全局热键（`RegisterHotKey`）做后门，避免锁上之后点不到菜单。

### R6 · 台词与情绪外部化（我补的）— P1 / S
把随机台词、气泡文案、低余额阈值提示抽到 `%APPDATA%\deepseek-pet\lines.json`（可编辑，不重编译）；余额越低台词越少/越丧，充值后说开心的话——情绪联动成本很低，但"活人感"提升明显。

### R7 · 省电与性能（我补的）— P2 / S
无操作 10 分钟后停粒子、降帧；轮询从 5 秒放宽到 10 秒且只在数据变化时重绘；立绘按需加载。目标空转内存 138 MB → < 80 MB。

### R8 · 多显示器 / 开机自启（我补的）— P2 / S
按显示器记住位置（config 存 `{displayId: {x,y}}`）；可选的"开机自启"（注册表 Run 或计划任务，默认关闭，设置里开）。

### R9 · 资源瘦身（我补的）— P2 / S
5 张 720px PNG 合计约 5.5 MB。降到 512px + 调色板量化可压到 ~1.5 MB。
**注意**：WPF 的 `BitmapImage` **不支持 WebP 解码**，别直接换 `.webp`；要压就走"缩尺寸 + PNG 量化"或改用 JPEG（但 JPain 没有 alpha，立绘不行）。

### R10 · 自检与回归（我补的）— P2 / S
给桌宠加 `--selftest`：检查 5 张素材存在/尺寸/alpha 覆盖率、离屏渲染一帧导出 PNG、自检 `stateUrl` 可达。改完素材不用肉眼盯屏幕，也方便以后进 CI。

### R11 · 分发与打包（我补的）— P2 / M
一键打包脚本（exe + assets + README + 示例配置）成 zip；插件若要上市场，需补 `README.en.md`、许可证、以及 R2 里说的商标免责声明。

### 建议的推进顺序

| 顺序 | 项 | 理由 |
|---|---|---|
| 1 | R1 消耗显示 | 你点名要的，改动最小、每天都能看到收益 |

### 10.1 省电改造（实测数据，同一台机器同一测法：12 秒 CPU 时间采样）

### 10.7 修掉一个从 v0.0.2 就潜伏的 bug：DragMove 吞点击

**症状**：点游戏屏没反应。加日志后确认 `OnScreenClick` 从未被调用（一行日志都没有）。

**根因**：`win.MouseLeftButtonDown += OnMouseDown` 里调用了 `win.DragMove()` —— 这是 WPF 的**模态拖动循环**，
它会捕获鼠标并吃掉随后的 `MouseLeftButtonUp`，因此屏幕边框上的 `MouseLeftButtonUp` 永远不会触发。
也就是说 v0.0.2 宣传的"点屏幕 = 招一只苦力怕"**从来没有真正生效过**（只有右键菜单那条路是通的）。

**修法**：在屏幕边框上把按下事件标记为已处理，窗口级拖动逻辑就不再介入：

```csharp
screenBezel.MouseLeftButtonDown += delegate(object s, MouseButtonEventArgs e) { e.Handled = true; };
```

**验证**（自动化点击，实测日志）：单选点击 `consumed=False` → 换游戏（vn → fp 画面确认）；
落在选项框内的点击 `consumed=True` → 选项消失、走进"自己呆在家里"支线、好感度 2 → 1。

**教训**：凡是"我实现了但没点过"的交互，都等于没实现 —— 这次是靠补日志 + 合成点击才抓到。

### 10.9 抠图工具把紫色染绿（v0.0.5 补修，用户发现）

**症状**：用户对比"自己给的设定图"和"实机立绘"后指出颜色不对——淡紫缎带发绿、蓝紫头发偏青。

**为什么我的自查没抓到**：我一直在看**分镜表/实机截图**，而它们在缩略图下"看着还行"；
真正抓住它的是**数值复核**：统计源图与资产的**平均 RGB**（去掉品红底、隔 3 采样）：

| 区域 | 源图 (R,G,B) | 修复前资产 | 修复后资产 |
|---|---|---|---|
| cloud（紫） | 207, 188, 214 | 196, **205**, 207（G +17 / B −7） | 202, 186, 210（−5, −2, −4） |
| star（蓝紫） | 141, 114, 160 | 128, **125**, 150（G +11） | 136, 112, 156（−5, −2, −4） |
| book（橙棕） | 194, 150, 141 | 191, 152, 139 ✓ | 192, 149, 141 ✓ |

**根因**：`pet-tools key` 的"去背景溢色"用了标准的反预乘公式 `c = (c − (1−a)·bg) / a`。
对**未被 alpha 混合、只是本身较亮的**柔和阴影像素，除以 a 会把 G 通道算爆（例如 R213, **G358→截断 255**, B238 = 白绿色），
于是紫/淡紫区域整体被推向绿色；橙棕色系不受影响，所以只有两只偏紫的角色出错。

**修法**：不做反预乘，改成**只按"品红程度"把 R/B 往 G 拉**（G 完全不动），并且只在半透明边缘生效：

```csharp
double mag = Math.Min(r, b) - g;          // >0 说明偏品红/紫
if (mag > 0 && al < 1.0) { double k = (1.0 - al) * despill; r -= mag * k; b -= mag * k; }
```

新增 `--despill 0..1`（默认 0.85，0 = 完全不去溢色）；三张立绘用新算法重抠后偏差收敛到 5 以内。

**教训**：①"看着差不多"不是验收，**颜色类问题要用数值对比**（这次是平均 RGB）；
②证据图会过期 —— 我把第一版生成的分镜图当成了当前素材发给用户，被抓了一次；现在 `assets/vn` 里的每张图都记了生成源与哈希。

### 10.11 「背景看不见 + 选项框点了不消失」：一个根因两个症状（v0.0.7）

**用户报告**：① galgame 里选项框点击后不消失；② 角色背后没有背景，像浮在空中。

**排查**：先查日志 —— 两次点击都记着 `consumed=True`，说明**点击其实生效了、选项也被选掉了**；
再查素材日志 —— `vn asset: bg_book.jpg` 也确实加载成功。两条线索都指向"逻辑没问题、**画面没刷新**"。

**根因**：`McVn.Render()` 是**增量绘制**（在上一帧的缓冲上画），但从来没清过缓冲。
于是"上一帧画过、这一帧不再画"的东西会**留在画面上**：

* 换角色后 `HideBuiltinBackground` 变 true → 不再画程序化渐变 → **旧渐变像素还留着，把真背景盖住了**（症状 ②）
* 选完选项后 `stage` 变 2 → 不再画选项框 → **旧框像素还留着**（症状 ①）

**修法**：`Render()` 开头 `Array.Clear(buf, 0, buf.Length);`（9600 个 int，代价可忽略）。
同时把"真背景上的暗化"从**硬边一条带**（y≥40）改成**渐变**（y 30→52 平滑到 0.5），
因为那条硬边本身就像"背景被切了一刀"。

**教训**：增量绘制 + 不清缓冲 = 幽灵残影；**"逻辑对了但画面不对"要优先怀疑缓冲/重绘**，
而不是去改交互逻辑（这次如果按表象去改点击判定，就会越改越偏）。

* 接口加 `void Panic()`，三块屏各自实现（MC 直接复用 `TriggerCreeper()`）。

* 删掉了原来那段"检测到 MC 死亡就切 work"的旧逻辑（line ~705），避免它抢在收屏动画之前切场景。

## 11. 美术与 IP 策略（第三方 logo 怎么处理）

| 与桌宠其他机制的接口 | 点屏幕 = 参与选择（被屏幕消费时不触发"换游戏"）；`OverlayText` 走窗口层，`Click(nx, ny)` 交给屏幕自己判定 |

## 12. 差异化定位：多交互 · 多动画（v0.0.x 主线）

同类桌宠插件基本是"可爱立绘 + 余额挂件"。我们的差异点是**交互密度与动画密度**：

**交互（能点、能拖、能玩）**
1. 拖动＝拎起悬空（R3），松手落地扬尘
2. 单击＝摸头（开心）／双击＝蹦跳
3. **点击显示器＝换游戏屏**（MC → 柚子社 → Steam → Xbox）
4. 前景道具可拖动：把水杯递给它、把零食拖到嘴边（会开心）
5. 滚轮缩放；右键菜单（表情 / 动画 / 场景 / 锁定穿透 / 退出）
6. DSH 侧：`pet_control` 让它说话、换表情、起停；余额变动自动播报

**动画（自己会干的事）**
7. 小动作池：伸懒腰 / 喝水 / 转笔 / 看手机 / 敲键盘 / 挠头 / 趴睡 / 玩游戏（权重 + 冷却调度）
8. 环境感知：深夜打哈欠、久无操作睡觉、DSH 干活时敲键盘、答完时欢呼
9. Minecraft 屏完整剧本：砍树 → 碎裂 → 计数 → 苦力怕 → 白闪 → You Died → respawn
10. 情绪联动：余额低＝肉疼/丧、充值＝撒花、被炸＝懵住 3 秒

**验收标准（每条都要看得见）**：随机观察 30 秒，至少出现 2 种不同动作；Minecraft 屏 5 分钟内至少触发一次苦力怕事件（概率可配）；连续观察 10 分钟不应出现同一动作重复——达不到就调权重。
**R2d 专项验收**：被"叫去干活"打断时，4–6 秒内能演完整条弧线（吓到 → 切屏 → 炸 → You Died → 复活 → 敲键盘）；10 分钟冷却期内再打断只演"叹气切屏"；自动续跑/子代理**不触发**；从事件发生到桌宠起反应 < 100 ms。
→ **R2d 已在 v0.0.2 实现并通过验收**（见第 9 节；"冷却期内改叹气"与概率护栏尚未做，是 R2d 的收尾项）。

### 13.1 为什么不拆成"她/桌子/键鼠"三层，而只做差分帧

预览图是一张**平涂整图**（1024×1024，洋红底 `#FF00FF`）。凡是"按区域把图切开再分层"的做法，
都会在切线上留下硬边 —— 这正是用户骂的"割裂"。而**保持整图像素不动、只把要动的小块以"补丁帧"盖上去**，
天然与原图逐像素对齐，不可能出现割裂。所以定稿方案是：

```
① 底图 = assets\desk\sit_watch.png（= 预览图抠掉洋红底，整图，永不再切）
② 差分帧 = 全画幅 1024×1024 透明 PNG，只有动的那一小块不透明（直接叠在底图上，坐标不用写进代码）
   · press_d / press_a / press_w / press_space  —— 键帽按下（内容整体下移 5px + 压暗到 74% + 顶部留插槽暗条）
   · press_mouse                                —— 鼠标下沉 6px + 轻微压暗（她的手指留在底图里，所以是"鼠标被按下去"的观感）
   · 表情帧（待做）                              —— 只覆盖脸部区域：常态/眨眼/开心/担心/困倦/看向你
```

**为什么键帽按下用"下移+压暗"而不是重画**：键帽在原图里**没有文字**（纯色矩形块），所以按下与否无法靠文字提示，
只能靠"下沉 + 变暗"表达；而这两步用代码逐像素做，比让模型重画一张更**精确且零漂移**。
小尺寸下的可读性也验证过：显示宽度只有 260 DIP（原图 1024），4–6px 的下移折算约 1–1.5px，
所以**真正承担识别的是压暗**，下移只是补充。
